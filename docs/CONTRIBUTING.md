# 贡献指南

## 1. 范围

欢迎以下类型的改动：

- 缺陷修复与构建兼容性修复；
- 布局、控件、事件与渲染抽象的改进；
- 文档纠错与示例补充；
- 性能与内存使用的可测量改进。

涉及框架公开接口、布局文档格式或 bin 格式的改动，请在同一次提交中更新对应模块的 `.md` 文档，并在提交说明里写清兼容性影响。

## 2. 编码风格

| 项 | 约定 |
| :--- | :--- |
| 语言 | C++17，MSVC，Windows 专有（C++20 亦可编译） |
| 缩进 | Tab |
| 大括号 | Allman（左括号独占行） |
| 类型 / 函数 | PascalCase；文件内静态函数也使用 PascalCase |
| 变量 | 松散 Windows 前缀 + PascalCase，如 `hWnd`、`dwCount`、`pszPath`、`pCtrl` |
| 布尔局部量 | `BOOL bRet`；成功置 `TRUE`，统一返回 |
| 类型 | 优先 `BOOL` / `DWORD` / `VOID` / `CONST` / `LPCSTR` / `FLOAT` 等 Windows 语义类型 |
| 别名 | 一律 `using`，不用 `typedef` |
| 常量 | `constexpr`，不用 `#define` 定义数值常量 |
| 头文件 | `#pragma once`；按 `<...>`、`"..."` 顺序包含 |
| 字符串 | `char` / `LPCSTR` / `u8"..."`，不用 `std::string` |
| 异常 | 不使用 `throw` / `try` / `catch` |
| RTTI | 不使用 `dynamic_cast` / `typeid` |
| 容器 | 不引入 STL 容器；使用手写数组、双向链表或内存池 |
| 内存 | 所有权明确、成对释放；会话内存取自 `Arena` / `MemPool` |
| 运行库 | 静态 `/MT`（Debug 为 `/MTd`） |

工程需开启 `/utf-8 /Zc:char8_t-`、`UNICODE`、`_AMD64_` 与 C++17；新文件不需要在源码内重复这些设置。

## 3. 注释约定

本仓库的注释刻意保持最少：

- 只保留函数两行注：

  ```cpp
  // 函数: DrawCtrl
  // 描述: 按控件类型分派并绘制一枚控件
  ```

- 不写文件头横幅、区域横幅、`说明:` / `注:` 段、行尾解释与实现流水账；
- 参数、返回值、失败口径、所有权、调用时序与副作用写在同目录的接口文档中；
- 注释一律纯文本：不使用 emoji，不使用 Markdown 标记（加粗、反引号等），强调靠措辞与分节；
- 代码与文档冲突时，以代码实际行为为准，先改文档、再改注释。

这条约定优先于个人习惯文件中的“高密度注释”偏好。

## 4. 文档

- 每个源文件模块配一份同目录 `<模块名>.md`，体例见 [INTERFACE-DOC-STYLE.md](INTERFACE-DOC-STYLE.md)；
- 文档为 UTF-8 无 BOM；中文正文用全角标点，代码与标识符用半角；
- 文档不写超链接、不写沿革、不写“另请参阅”；
- 每份文档末尾有且只有一个 `## 要求` 节（标头 / 实现 / 命名空间 / 依赖 / 平台 / 线程安全）；
- 新增模块时，文档与原文件同一次提交，并把新源文件加入你自己的构建工程。

## 5. 构建与自检

提交前至少执行：

按 [BUILD.md](BUILD.md) 用 Visual Studio 或 `cl` 构建 Release。

判据：

- 0 警告、0 错误；
- 生成 `Kanat.exe`；
- 把 `docs/examples/Kanat.json` 复制到 exe 同目录后运行，退出码 0；
- 改动涉及布局或控件时，核对启动日志中的控件数、层次与坐标。

## 6. 提交与合并请求

- 一次提交只做一件事；格式整理与行为改动分开；
- 提交说明写清“改了什么、为什么、如何验证”；
- 不提交 `out/`、`_tmp/`、日志、截图与本地备份；
- 不提交密钥、令牌、个人路径或机器专属配置；
- 合并请求请附构建结果与运行结论；涉及界面的改动附文字说明，交互观感标注“需本机人工复核”。

## 7. 新增模块清单

1. 新建 `Xxx.h` / `Xxx.cpp`（纯头文件模块可只有 `.h`）；
2. 写 `Xxx.md`，按接口文档体例列出公开面；
3. 把新源文件加入你自己的构建工程；
4. 在所属层的文档索引或架构文档中补一行说明；
5. 构建并运行。
